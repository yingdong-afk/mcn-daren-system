# 抖音 MCN 达人商务自动化管理系统

可实际运行的第一阶段 MVP：中文网页、真实达人数据库、可解释筛选、个性化邀约草稿、商务联系与跟进、合作进度、Excel / CSV 导入和员工工作统计。

采用 Python 3.12 + Flask + SQLite。无需安装独立数据库或配置外部 AI 服务。初始化后的业务数据库为空；不会生成虚构达人，不运行爬虫，不自动对外发送消息。

## 第一次启动（推荐）

**不熟悉命令的 Windows 用户：** 安装 Python 3.12，将 GitHub 下载的代码 ZIP 完整解压，双击项目里的 `启动系统.bat`。它会自动安装依赖，首次让您设置管理员密码，然后启动服务并打开本机浏览器。登录账号为 `admin`。保持启动窗口打开；关闭窗口或按 Ctrl+C 会停止服务，数据保留。首次安装依赖需要联网。此操作在您自己的电脑执行，不是云环境的公网预览。

在项目目录打开终端，执行：

```bash
bash scripts/setup.sh
.venv/bin/flask --app app:create_app init-admin
bash scripts/start.sh
```

第二条命令会让您输入两次管理员密码（至少10位，输入时屏幕不显示）。默认登录账号是 `admin`。**没有默认密码**，不要把密码放到命令行、代码或聊天中。已有账号不会被覆盖。

服务默认监听本机 `127.0.0.1:8080`。在运行服务的电脑上用浏览器打开该地址并登录。关闭终端里的服务时按 Ctrl+C，之后重新执行 `bash scripts/start.sh` 即可，数据保留。云环境访问方式取决于部署平台，当前 onboarding 界面不提供网页预览。

如果不使用 Linux/macOS 的 Bash（如 Windows），使用 Python 3.12 执行：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\flask --app app:create_app init-admin
.venv\Scripts\waitress-serve --host=127.0.0.1 --port=8080 --call app:create_app
```

推荐使用北京时间一致的真实统计周期文本，例如日期范围。所有联系及跟进时间按 `Asia/Shanghai` 保存和显示。

## 实际业务操作

1. 管理员在“员工管理”中开通商务员工账号，可选择员工或管理员角色；员工登录后可修改自己的密码。
2. 在“达人数据库”录入昵称、抖音号、粉丝数量、带货类目、内容类型、联系方式、历史销售额、销售统计周期、数据来源和备注。未知数据留空，已知为零才填0。
3. 管理员分配负责人；员工新建/导入的档案自动归自己，也可认领未分配档案。所有登录用户可查看团队数据库，只有负责人或管理员可编辑档案、记录联系或变更进度。
4. 在“智能筛选”填写产品类目、内容类型、粉丝区间、销售周期和目标销售额，查看每项分数、依据及数据缺失提示。
5. 打开达人详情，填写产品和真实合作条件生成邀约草稿。根据实际情况审阅、复制，并由员工手动联系达人。
6. 保存联系时间、回复内容、跟进状态和下一次跟进时间；每次跟进追加一条商务联系记录。提醒以每位达人最新的联系记录为准，已完成或无需跟进不再提醒。
7. 根据真实依据更新：**待联系 → 已联系 → 已回复 → 已寄样 → 已拍摄 → 已发布 → 已成交**。允许更正/回退，每次变更须填写依据，记录操作员工、时间和原/新状态。联系记录不会自动改变合作状态。
8. 在“业务总览”查看各状态数量、当前成交占比、员工负责达人、累计/今日联系次数、成交达人及到期跟进。

第一阶段每位达人维护一条当前合作进度。多个品牌/产品并行合作、物流接口、作品效果同步、独立订单和佣金结算台账属于后续扩展。当前“已成交”是人工确认的合作状态，统计中的成交占比不是订单量、GMV或阶段转化率。

## 智能筛选的真实规则

采用可解释规则评分，不依赖大模型猜测。

| 维度 | 满分 | 计算方式 |
| --- | --- | --- |
| 粉丝匹配 | 25 | 在目标区间内25分；低于区间为25×粉丝/最低值；高于区间为25×最高值/粉丝 |
| 内容类型 | 25 | 已录入标签与目标类型精确匹配25分，否则0分 |
| 带货能力 | 25 | 仅同一周期：25×历史销售额/目标额，封顶25分；不预测销量 |
| 产品类目匹配 | 25 | 已录入类目与产品类目精确匹配25分，否则0分 |

标签以逗号、顿号或分号分隔；不进行模糊语义推断。统计周期文本必须一致，不会将不同周期销售额混算。缺失数据或周期不一致的项记为“数据不足”，而不是0分；只有四项数据齐全才显示100分制综合分。数据不全时展示“已知项得分 / 已知项满分”和完整度，先按完整度排序，再按已知得分排序。分数仅辅助人工判断，数据来源真实性仍需核验。

## Excel / CSV 导入

“批量导入”页面可以下载仅含表头的空白 CSV 模板。在 Excel 填写真实数据后保存为 `.xlsx` 或 CSV。只读取 Excel 的第一个工作表；抖音号包含前导零时应将单元格设为文本。手机号也建议设为文本。

| 中文表头 | 必填 | 说明 |
| --- | --- | --- |
| 达人昵称 | 是 | 最多300字 |
| 抖音号 | 是 | 字母、数字、下划线、点、短横线，最多100字符 |
| 粉丝数量 | 否 | 非负整数，不支持“万”等单位 |
| 带货类目 | 否 | 多标签用中文逗号等分隔，自动去重 |
| 内容类型 | 否 | 同上，用于内容评分 |
| 联系方式 | 否 | 经授权保存的商务联系方式 |
| 历史销售额（元） | 否 | 非负金额，最多两位小数 |
| 销售统计周期 | 有销售额时必填 | 使用明确、一致的周期文本 |
| 数据来源 | 否 | 来源、授权依据、采集日期等 |
| 备注 | 否 | 最多2000字 |

支持 UTF-8（包括 BOM）及 GB18030 CSV，文件最大5MB、最多5000行，Excel解压内容不超过40MB。不接受公式及以 `= + @` 开头的单元格。抖音号不区分大小写去重，文件内重复与数据库重复均跳过，不覆盖现有资料。未知列或重复表头会拒绝文件；数据校验失败显示行号，合法行正常保存，修正后重新导入即可。

## 测试与验收

```bash
.venv/bin/python -m pytest -q
```

测试包括空库、登录/CSRF、员工越权限制、录入编辑搜索、大小写去重、CSV/Excel导入与公式拒绝、无效文件/超限处理、数据不足、同周期评分、邀约草稿、七阶段状态审计、认领、联系跟进、提醒、账号管理、密码更改及登录失败限流。合成数据只写入 pytest 临时数据库，不写入 `instance/mcn.sqlite3`。

手工验收可录入您掌握的一位真实达人，依次执行查询、筛选、话术生成、记录联系和更新进度，再重启服务检查档案仍存在。上传真实名单两次，第二次应显示重复跳过。未知销售数据必须显示“数据不足”，不能出现推算金额。

运行中的健康检查：

```bash
curl --fail http://127.0.0.1:8080/health
```

预期返回 `{"status":"ok","database":"ok"}`。健康检查只说明服务/数据库可用，完整业务由上述测试及手工步骤验证。GitHub Actions 配置会在 push / pull request 时运行基础测试。

## 配置、部署和备份

本地无需 `.env`。下列环境变量可选：

| 名称 | 默认 | 用途 |
| --- | --- | --- |
| `MCN_INSTANCE_DIR` | 项目 `instance/` | 数据库及会话密钥所在目录；必须可写 |
| `MCN_HOST` | `127.0.0.1` | `scripts/start.sh` 的监听地址 |
| `MCN_PORT` | `8080` | `scripts/start.sh` 的端口 |
| `MCN_SECRET_KEY` | 首次生成并保存 | 可选固定会话密钥，需至少32字节随机值；不要写入Git |
| `MCN_HTTPS` | 未启用 | HTTPS部署时设为 `1`，使会话Cookie仅经HTTPS发送 |

部署使用 Waitress，无调试模式。SQLite适合单实例、小团队 MVP。对公网提供服务时，使用域名与 HTTPS 反向代理，设置 `MCN_HTTPS=1`，限制为公司需要的访问范围。当前按实际连接IP进行登录失败限流：15分钟内10次失败后暂时拒绝登录；反向代理后的多名员工可能共享这个限额，生产代理应配置独立登录速率限制。本版不配置可信代理头，不信任用户传入的 `X-Forwarded-For`。

可选 Docker 启动：

```bash
docker compose up -d --build
docker compose exec web flask --app app:create_app init-admin
docker compose logs --tail=50 web
```

Docker 默认将服务绑定到宿主机本地8080端口，数据存放在持久卷 `mcn-data`。停止时使用 `docker compose down`，**不要加 `-v`**，否则会删除业务数据。

本轮已验证 Compose 配置格式。云开发环境的 Docker 构建在依赖安装阶段因容器 DNS 无法解析 PyPI / 网络代理地址而失败，尚未验证容器启动；需要在网络正常的 Docker 部署机器验证。前面的 Python 直接安装、启动、真实 HTTP 操作和重启持久化均已通过，不依赖 Docker。

本机 SQLite 在线备份：

```bash
.venv/bin/python scripts/backup.py /tmp/mcn-backup.sqlite3
```

输出文件不允许已存在，使用 SQLite 在线备份API且验证数据库完整性，可在服务运行时备份。请将备份安全转存到公司存储。恢复时先停服务，将备份替换 `instance/mcn.sqlite3`，清除旧的 `mcn.sqlite3-wal` / `mcn.sqlite3-shm` 后重启。保留原数据库作为恢复前副本。`session.key` 不在数据库备份内，恢复时缺失会自动生成新密钥，员工需要重新登录。不要只复制运行中主数据库文件，会遗漏 WAL 中的数据。

`instance/`、虚拟环境和密钥均已忽略，不应提交Git。请只保存有处理依据的数据，建立公司保留/删除制度，不在公开环境放置真实手机号及商务资料。

## 后续自动化扩展

当前只提供会话认证的读取与评分接口，需先网页登录；JSON POST 还需 `X-CSRF-Token`（当前会话的表单CSRF值），不支持无认证写入或自动发信。

| 接口 | 方法 | 功能 |
| --- | --- | --- |
| `/api/v1/capabilities` | GET | 功能声明，采集及自动联系均为关闭 |
| `/api/v1/talents?after_id=0` | GET | 最多100条，使用返回的 `next_after_id` 翻页；不返回联系方式 |
| `/api/v1/talents/<id>/score` | POST | JSON规则评分，参数同筛选表单 |

评分JSON字段：`min_fans`、`max_fans`、`target_gmv`（元）、`category`、`content_type`、`sales_period`。响应包含 `dimensions`、`coverage`、`observed`、`known_max` 和 `total`，缺失数据用 JSON `null`。

`extensions.py` 定义授权公开信息来源、人工确认后商务联系的适配器协议。第一阶段没有具体采集或发送实现，也没有后台自动任务。后续优先接入官方或获授权的数据API；保留数据来源和授权依据，明确人工确认、拒绝联系和频率限制后再开启能力。

## 代码结构

```text
app.py                  Flask应用、权限、网页与API
domain.py               数据校验、可解释评分、导入、邀约模板
schema.sql              SQLite表与索引
extensions.py           后续自动化适配器契约
templates/              全中文网页
static/style.css        响应式样式
tests/                  隔离数据库基础测试
scripts/                安装、启动、在线备份
```

云任务已运行在隔离环境中，使用现有仓库即可，无需另建 Git worktree。依赖安装不添加假数据，服务进程重启后数据库继续复用。
